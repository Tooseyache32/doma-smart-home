# DOMA — умный дом в твоём ритме

Полноценный русскоязычный full-stack учебный проект: **5 пользовательских страниц + админ-панель**, регистрация, роли, связанная SQLite БД, управление виртуальными устройствами и журнал событий.

**Важно:** это симулятор, а не интеграция с физическим оборудованием. Команды, показания, сценарии и расписания обрабатывает сервер, состояние сохраняется в файле БД.

## Быстрый запуск

Требуется **Node.js 22.22+** и npm. Используется встроенный `node:sqlite`; отдельный SQLite/PostgreSQL-сервер не нужен. Node 22 может выводить предупреждение об экспериментальном SQLite — это не ошибка.

```bash
npm install
npm run dev
```

Откройте **http://localhost:5173**. API работает на порту 3001, Vite проксирует `/api` с сохранением исходного Host для проверки Origin.

На экране входа нажмите **«Попробовать демо»** или используйте:

| Роль | Email | Пароль |
|---|---|---|
| Пользователь | `alex@doma.local` | `DomaHome2026!` |
| Администратор | `admin@doma.local` | `DomaAdmin2026!` |

Эти аккаунты автоматически создаются только в development. Обычная регистрация создаёт отдельный дом с виртуальными устройствами и не открывает доступ к чужим данным.

## Страницы и возможности

- **Обзор** `/`: состояние дома, комнаты, быстрые сценарии, климат, свет и последние события.
- **Свет** `/lighting`: фильтр по комнатам, переключение, яркость, цветовая температура, добавление/редактирование/удаление.
- **Климат** `/climate`: целевая температура, режимы, включение, показания воздуха и история датчиков.
- **Сценарии** `/scenes`: пресеты, создание/редактирование нескольких действий, ручной запуск, расписание по времени и дням недели.
- **Датчики и события** `/activity`: виртуальные датчики, тестовые показания, история, поиск и фильтры журнала, пагинация, экспорт CSV.
- **Админ-панель** `/admin`: формы для всех бизнес-таблиц, справочников и связей; управление пользователями, сброс пароля и отзыв сессий. Хеши не отображаются.
- Профиль, дом и комнаты — через меню и диалоговые формы. Служебные `/login`, `/404`, `/500` не входят в пять основных страниц.

Устройства, участвующие в сценариях, нельзя удалить до удаления соответствующих действий. В админке защищено удаление последнего администратора и последнего владельца дома. Физические интеграции, SMS, реальные камеры, погодный API и удалённое управление оборудованием не реализованы и не имитируются как подключённые сервисы.

## Команды

```bash
npm test           # backend-интеграционные тесты, изолированные БД
npm run build      # проверка TypeScript и production-сборка frontend
npm run seed       # идемпотентное создание схемы/начальных данных
npm start          # API; при NODE_ENV=production также раздаёт dist
```

Схема, внешние ключи, ограничения, индексы и миграции создаются при старте. Данные по умолчанию: `data/doma.sqlite`. Не удаляйте этот файл для перезапуска: данные должны сохраняться. Не коммитьте БД, `.env`, пароли или резервные копии.

## База данных и безопасность

Описание связей и аргументация 3НФ: [docs/database.md](docs/database.md).

- Пароли: **scrypt + случайная соль**. Хеширование не является обратимым шифрованием.
- Случайные токены сессий и CSRF хранятся только как хеши; сессионная cookie `HttpOnly`, `SameSite=Lax`, `Secure` в production.
- Проверка сессии, роли и принадлежности дому на сервере; пользователь не может открыть чужой дом подменой ID.
- CSRF-токен и строгая проверка Origin для изменений; лимиты запросов и размера JSON.
- SQL-запросы параметризованы. Динамические имена таблиц и полей берутся только из серверного whitelist.
- React выводит пользовательские строки как текст; нет вставки пользовательского HTML. Helmet/CSP и скрытие внутренних ошибок.
- Клиентская и серверная валидация значений; понятные ошибки форм, уведомления, состояния загрузки и пустых данных.
- CSV экранирует строки и опасные формулы.

## Развёртывание

Публично сайт автоматически **не размещается**. Для production создайте отдельную БД и собственные секреты; не используйте development-БД с известными паролями.

Пример `.env` (на базе `.env.example`):

```dotenv
NODE_ENV=production
PORT=3001
DB_PATH=./data/production.sqlite
ADMIN_EMAIL=your-admin@example.com
ADMIN_PASSWORD=long-unique-secret-at-least-10-characters
PUBLIC_ORIGIN=https://home.example.com
TRUST_PROXY=1
ENABLE_SIMULATION=true
```

`ADMIN_EMAIL` и `ADMIN_PASSWORD` используются только при первоначальном создании администратора в пустой production-БД. После первого запуска удалите пароль из конфигурации развёртывания и храните секреты в защищённом менеджере. Демо-вход отключён в production. Симулятор можно отключить `ENABLE_SIMULATION=false`; реальная аппаратная интеграция от этого не появляется.

```bash
npm ci
npm run build
npm start
```

Перед приложением настройте **HTTPS reverse proxy** (например, Nginx/Caddy), сохраняющий Host и передающий корректный `X-Forwarded-Proto`. `TRUST_PROXY=1` допустим только при одном доверенном прокси, если прямой доступ к API закрыт. Не включайте доверие к произвольным прокси. `PUBLIC_ORIGIN` должен точно совпадать с адресом в браузере.

SQLite требует **постоянного локального тома**, а не временной файловой системы serverless. Для этого учебного проекта рекомендован один экземпляр приложения. Настройте резервное копирование согласованным SQLite backup API; не копируйте только `.sqlite` во время записи без учёта WAL. Несколько независимых серверов и большая нагрузка потребуют перехода на PostgreSQL.

Есть `Dockerfile` для Node 22 и volume `/app/data`; Docker-сборка в текущей среде не проверялась, поскольку Docker отсутствует. При контейнерном запуске передайте production-переменные и подключите постоянный том.
